# Plan — Salem: own OS user, own gateway — as immediate as possible

Date: 2026-11-13 · Depends on #140 (merged; deploys in the same switch)

## Principle

One PR, one switch, tonight. Everything she has — memory, skills, settings, cron
history, hooks, checkpoints — moves with her, copied from a **stopped** unit so the
databases are consistent. The original profile dir is never touched: rollback is
`git revert` + one switch. We do **not** wait for her cron windows; her next fire
(23:00 Вечерний отчёт) is hours away and the cutover gap is minutes.

## Phase 0 — verified facts (done, don't redo)

- Token isolation: her PID holds exactly one `TELEGRAM_BOT_TOKEN` — hers
  (`8971786164 @Hermes_Salem_Gera_bot`). The 14:35 `polling conflict (1/5…5/5)` was
  Telegram holding the old `getUpdates` session after the SIGTERM restart, not a
  shared token.
- She inherits `/run/secrets/hermes/env`, which accidentally enables an API server
  **listening on 0.0.0.0:8643 and 8644** — declared nowhere, used by nobody. Giving her
  unit only her own env file removes it.
- `terminal.cwd: /Storage/Git/spectacle` does not exist on serenity → 1 warning / 2 s
  (2,193 since boot).
- **Env enumeration complete**: her config references exactly one secret variable —
  `HERMES_CUSTOM_NEURALWATT_API_KEY` — plus her `TELEGRAM_BOT_TOKEN`. The list is closed.
- **Trilium MCP is world-readable** (`755 hermes:hermes`, file `644`) → a new `salem`
  user can read it in place; no copy, no retarget.
- `food_log` MCP runs `/run/current-system/sw/bin/python3` → user-independent.
- Profile: **293 MB** (checkpoints 173M, logs 61M, state.db 24M, skills 12M, sessions
  4.2M, plugins, cron, agent-hooks, bin, food.db, food_diary, auth.json, .env).
- `salem-eval` stays with `hermes`. Out of scope.

## Phase 1 — one PR, now: `feat(hermes): run salem's gateway as a dedicated OS user`

1. **User**: `users.users.salem` — system user, group `salem`, home `/var/lib/salem`,
   `linger = true`.
2. **Secrets**: new sops template `salem/sops-env`, owner `salem`, group `salem`,
   mode `0400`. Contents (closed list): her `TELEGRAM_BOT_TOKEN`,
   `HERMES_CUSTOM_NEURALWATT_API_KEY`. Old `hermes/salem-sops-env` stays until Phase 3.
3. **Unit** — explicit `hermes-gateway-salem`, replacing the
   `extraHermesProfiles`-generated one:
   - `ConditionUser=salem`, `wantedBy=[default.target]`, `Restart=always`,
     `RestartSec=5`, `TimeoutStartSec=240`.
   - `HERMES_HOME=/var/lib/salem/.hermes`, `HERMES_PROFILE=salem`, bundled
     `HERMES_BUNDLED_*` → `${hermes-pkg}/share/hermes-agent/...`,
     `HERMES_LAZY_INSTALL_TARGET=/var/lib/salem/.hermes/lazy-packages`.
   - `EnvironmentFile = [ salem/sops-env ]` **only** — never `/run/secrets/hermes/env`.
   - `API_SERVER_ENABLED=false` (the 8643/8644 listener was accidental).
   - Both #140 pre-steps pointed at her `state.db`: `hermes-pm-reconcile`
     (bounded 300 s, non-fatal) and the db-swap.
4. **Migration activation script** (idempotent): if `/var/lib/salem/.hermes` is absent
   and the old profile exists → `rsync -a --chown=salem:salem` the **whole profile
   directory** (nothing cherry-picked — memory, skills, checkpoints, sessions, cron,
   hooks, `auth.json`, `.env`, `food.db`, `food_diary` all move), then delete runtime
   junk (`gateway.lock`, `gateway.pid`, `gateway.sock`, `gateway_state_*.tmp`).
   Exclusions: `cache/`, `tools/.staging-*`, `audio_cache/` (regenerable).
   Also `mkdir -p /var/lib/salem/workspace`. Original stays = rollback.
5. **Config edits on the migrated copy** (same script, idempotent):
   - drop `gateway.standalone: true`;
   - `terminal.cwd` → `/var/lib/salem/workspace`;
   - drop the dead `github` MCP entry (`git` already disabled);
   - trilium MCP path unchanged (world-readable, verified).
6. **Remove salem from `extraHermesProfiles`** — her unit is explicit now.
7. **Gates**: `nix eval` assertions — unit exists with `ConditionUser=salem`, env file
   owned by salem, no `/run/secrets/hermes/env` in her unit.
   **VM smoke skipped on purpose** — speed is the priority; the host verification in
   Phase 2 is the real gate.

## Phase 2 — merge and switch, immediately after checks

1. **Backup block (one continuous stop→copy→switch, ~10 min downtime)**:
   `systemctl --user stop hermes-gateway-salem` → sqlite `.backup` of `state.db` and
   `cron/executions.db` → `tar` the profile dir → rsync offsite to poweredge (forgejo
   recipe). The stop guarantees a consistent copy; no live-writer corruption possible.
2. PR → checks → merge → `sudo nixos-rebuild switch --flake .#serenity`
   (this switch also lands #140 for both gateways).
3. **Verify (~15 min)**:
   - unit active, PID runs as `salem`, 0 restarts;
   - `getMe` = `@Hermes_Salem_Gera_bot`; journal shows
     `Connected to Telegram (polling mode)`;
   - expect ≤5 polling-conflict retries ≈ 6 min of quiet inbound (inherent to restart);
   - `pm doctor` 9 green as `salem` (first reconcile is bounded and non-fatal);
   - all 5 cron jobs present, `executions.db` history intact;
   - **zero** `TERMINAL_CWD` warnings after 10 min;
   - nothing listening on 8643/8644;
   - skills/checkpoints/sessions present under her new home.
4. **Functional proof**: message her once on Telegram — the reply is the end-to-end test
   (paid call, trivial cost).
5. **Rollback**: revert the commit, switch. The old generated unit returns and points at
   the untouched original profile dir.

## Phase 3 — cleanup PR (after a few green days)

Delete `hermes/salem-sops-env` secret + template, delete
`/var/lib/hermes/.hermes/profiles/salem`, drop the copy branch from the migration
script.

## Risks

- **Env file incomplete** → she won't start. Enumeration is already done and closed
  (one variable + her token); rollback costs one switch.
- **executions.db** — copied from a stopped unit by construction; skipping it would
  re-fire catch-ups.
- **Missed cron during the gap** — window is clear until 23:00; worst case one
  catch-up or one skip.
- **PM first boot under a new home/UID** — pre-step reconciles, bounded, non-fatal.
- **Fewer gates than the slow plan** (no VM smoke) — accepted for speed; the host
  verification list replaces it.

## Defaults chosen for speed (override freely)

`terminal.cwd` → `/var/lib/salem/workspace` · VM smoke → skipped · API server → off ·
trilium MCP → stays shared (world-readable) · full-profile copy (nothing cherry-picked).
